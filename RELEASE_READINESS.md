# Release readiness

Review date: 2026-10-30

## Status

The local application flow and core backend have been exercised on Linux with MariaDB. The sidebar, local no-login startup, and profile panel have been verified in Chromium at desktop and mobile sizes. This worktree is **not yet verified for customer release on Windows**: the MariaDB provisioning script, packaged Tauri installers, WebView2 runtime, and hard-interruption recovery still require Windows execution.

Fiscal documents are draft records only. The app does not build legally complete invoices or integrate a certified issuer. The issue endpoint returns HTTP 503 before a database mutation or outbound request, and the UI neither accepts provider credentials nor offers an issue control. Provider integrations are also scaffolding: their endpoint check does not verify provider credentials, and the generic webhook is not a provider-specific connector.

## Operating constraints

- This is a single-computer local app with no login prompt. The Windows account and physical access to the computer are the user boundary. There are no per-employee permissions.
- The optional courier/public-menu LAN listener exposes a narrow set of endpoints; the management API remains on loopback. Configure trusted HTTPS and firewall access before enabling it.
- Customer QR codes contain a URL. Local QR generation works offline, but remote phones need network access to that URL.
- Fiscal records are drafts; do not use them as tax documents or claim that they were submitted to a tax authority.
- A fresh Windows machine still needs MariaDB installed and provisioned before the app can serve as a complete out-of-box installation.
